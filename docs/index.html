The problem

Every AI session starts from zero. Your repo shouldn't.

You re-explain the same context

Every new agent, every new session: the stack, the constraints, the reason the obvious approach was rejected. Again.

Decisions evaporate

The reasoning behind the code lives in someone's head, or in last week's chat. The next agent, even a smarter one, re-decides it.

Memory gets locked in

What one tool remembers sits in that tool's schema. Switch agents and the history is gone, or unreadable.

How it works

Three steps. Then every agent reads the same files.

Full quickstart
01 · INSTALL

Run the installer

Idempotent. Re-running never overwrites existing entries or the contract.

sh path/to/codicent-muse/install.sh
# Windows: .\install.ps1
02 · TEACH

Add the agent snippet

Fifteen lines in AGENTS.md or CLAUDE.md: where memory lives, read before acting, write after.

cat template/AGENTS.snippet.md \
  >> AGENTS.md
03 · USE

Commit and ask

The agent reads the logbook at session start and appends an entry after it acts. Same diff, same review.

The whole schema
  1. Entries are dated Markdown files with frontmatter and tags.
  2. An index lists them chronologically, newest last.
  3. Every entry links the commits, PRs and dates it concerns.
  4. Agents read the logbook at session start.
  5. Agents write an entry after they act.
Read the schema 
.codicent/
├── CONTRACT.md              # the memory contract
└── logbook/
    ├── index.md             # chronological, newest last
    ├── 2026-10-29-why-x.md  # one file per entry
    └── templates/           # decision · tacit · release

Where this goes

The kit is step one. Codicent is the memory.
